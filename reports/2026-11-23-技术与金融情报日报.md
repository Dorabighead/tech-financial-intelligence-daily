#### 1. MiniMax：大模型首次把多个 NIST 候选密码算法从「理论攻击」推进到可执行攻击（待复核）
- **发生日期**：2026-11-22
- **事件**：MiniMax 公布内部模型在密码分析上的成果。团队用大模型分析历届美国 NIST 密码标准化竞赛候选算法，发现多处此前未知的构造缺陷，把原本停留在理论层面的攻击推进到**秒级、分钟级可执行**，首次攻破多个此前没有任何已知实际攻击的方案；范围还扩展到密码学顶会论文与竞赛优胜方案，对若干经同行评审的构造实现**认证密文伪造或密钥恢复**。数学侧，模型在公开挑战赛中首次解出数十个无公开解的高阶问题，速度比现有最优算法快数百至数万倍。公司强调**不影响现行主流密码标准**，推理轨迹与技术报告已公开待复核。

#### 2. 米哈游开源 VLA 基础模型 Gamer：不读游戏接口，只看画面自己玩《崩铁》50 小时
- **发生日期**：2026-11-21
- **事件**：米哈游崩坏 AI 团队公开 VLA（视觉-语言-动作）基础模型 **Gamer**，主力版本以 **80 亿参数 Qwen3-VL-8B** 为基座，**只吃屏幕画面与任务指令、不读游戏接口**，自己决定按键与点击。在覆盖 5 个主线篇章、约 50 小时的《崩坏：星穹铁道》里，自主运行时间占比 **超 95%**；在 40 个未训练的小游戏任务上，成功率从基座的 **3.2% 提升到 49.7%**，同期最强通用模型为 17.1%。工程手法包括「稀疏思考」（只在路线失败或目标切换时推理）、「记忆摘要」压上下文，配合 Streaming-vLLM 做到 **200ms 读帧、30Hz 出动作**。
- **为什么值得关注**：价值不在「AI 打游戏」，而在**纯视觉闭环 + 长时程自主率**这两个可迁移指标。不依赖内部 API 意味着同一套方法可平移到任意 GUI 软件（这与本周 GitHub 热榜上 CLI-Anything、t3code 的方向互为镜像：一边把软件改造成 agent 可调用的接口，一边让 agent 直接适应人类界面）。「50 小时 / 95% 自主」比单步成功率更能说明长上下文与错误恢复的真实水平；稀疏思考 + 记忆摘要是抑制推理成本的关键，对做 Agent Runtime 的团队有直接参考意义。
- **来源**：[每日 AI 新闻速览 2026-11-22（量子位 / arXiv 论文页）](http://mp.weixin.qq.com/s?__biz=MzI2NDQyNDU4MA==&mid=2247484431&idx=1&sn=e69e2b3006862ae6827b54fab59699fe#rd)

#### 3. 字节 Axion 1.0 开源：智能体后训练压缩为「两段 SFT + 一段 RL」，教材仅 534MB
- **发生日期**：2026-11-21（论文 11 月初已挂 arXiv）
- **事件**：字节跳动与杜克大学、马里兰大学等团队公开智能体基础模型 **Axion 1.0** 的代码、数据配方与 **35B 权重**（arXiv 2611.03233）。后训练砍成两段轻量监督微调 + 一段强化学习，**跳过中期训练、DPO 与在线策略蒸馏**；全部教材只有 **18,847 条轨迹、534MB**，SFT 仅耗 **90 GPU 小时**。成绩：122B 版在 HLE 拿 59.0（低于 Claude Fable 5 的 63.8），35B 版在 SEAL-0 反超到 62.2。**注意**：公开的 35B 权重是社区复现版，成绩最好的 122B 并未放出。
- **为什么值得关注**：这条把「Agent 后训练究竟需要多少数据与算力」的门槛又往下压了一个数量级——534MB 教材、90 GPU 小时意味着一个中小实验室可以完整复现一条 agent 训练流水线，而不是只调 API。更值得留意的是**「跳过 DPO 与在线策略蒸馏」**：如果可复现，说明当前主流后训练配方里有相当部分是冗余的，这对 inference-time 优化与私有化部署的成本模型是实质性利好。但「放出的不是最好的那个权重」是常见套路，复现前需按论文口径核对评测集。

#### 8. Context Engineering：Gemini Tool Retrieval 预览、英伟达研究员质疑超长上下文
- **发生日期**：2026-11-21（provider snapshot）
- **事件**：**Gemini Tool Retrieval** 进入预览——在 Gemini Interactions API 中，agent 可**保留大量工具的名称与描述，仅在需要时加载完整参数 schema**；目前要求 `v1beta`、不支持旧 `generate-content`，且服务端检索会触发一次额外计费的模型调用。同日，英伟达研究员提出**大规模上下文窗口低效且昂贵**，主张用周期性摘要 + 关键词搜索替代全上下文处理。相关工程信号：OpenAI 把 Codex 的 WebSocket 请求上限从 **16MB 提到 128MB**；DeepSeek 通过 API 开放网页搜索、深度搜索、文件与链接解析、安全筛查、TTS 与 ASR；Claude Code stable 从 `v2.1.311` 推进到 `v2.1.323`（`v2.1.330` 为最新构建），修复对话压缩后多分钟冻结、误删其他会话 worktree、并发保存丢设置等问题。

#### 1. Java4Shell（CVE-2026-114938）：OpenJDK Base64 解码路径可致 RCE，国家级预警已发
- **发生日期**：2026-11-17 境外披露 / **11-19** 国家网络安全通报中心发布预警 / 11-22 安全简报补记修复镜像
- **事件**：境外安全研究机构 Calif 披露 **Java4Shell（CVE-2026-114938）**，漏洞存在于 **OpenJDK Base64 解码路径**：攻击者向 Java 应用提交特制 Base64 数据可触发**堆内存越界写入**，造成敏感信息泄露甚至远程代码执行。Oracle 已紧急发布修复版本，**JDK 21 修复镜像已出**；官方提示大量暴露于互联网的 Java 应用极易成为攻击目标。
- **为什么值得关注**：Base64 是几乎每个 Java 服务入口都会经过的基础路径（Header、Token、上传内容、签名校验），影响面远大于某个框架漏洞，且**不需要认证即可触达**。这类「标准库级」漏洞的修补难点不在补丁而在资产清点——大量内嵌 JRE 的中间件、老旧容器镜像不会被常规依赖扫描覆盖。建议本周把 JDK 版本盘点与基础镜像重建列为优先项。
- **来源**：[光明网：国家网络安全通报中心发布 JAVA 远程代码执行高危漏洞预警（11-19）](https://legal.gmw.cn/2026-11/19/content_39109698.htm)、[每日安全简报 2026-11-22](https://nanadol.com/archives/security-daily-2026-11-22)

#### A.2.1 NGINX 十年未认证 RCE（CVE-2026-123007）
- **发生日期**：2026-11-18 公开

### A.5 数据校验方法论补记：英伟达「日期错位稿」识别

- **发生日期**：2026-11-21（相关稿件）
- **事件**：关于英伟达 11-20 收盘，检索命中两组数字：**甲组** `收盘 145.98 美元 / 市值 3.52 万亿 / 连跌 6 日`（京报网 11-21 稿）、**乙组** `收盘 125.53 美元 / 市值 3.03 万亿 / 连跌 7 日 / −14.01%`（第一财经、华尔街见闻、财经早餐）。表面看是「媒体数据打架」。
- **为什么值得关注**：一组简单算术即可判定二者**自洽地构成相邻两个交易日而非矛盾**：`145.98 × (1 − 14.01%) = 125.53`；`3.52 − 3.03 = 0.49 万亿 ≈ 4928 亿`，与第一财经「一夜蒸发约 4928/4850 亿美元」吻合。故甲组实为 **11-19 收盘**、乙组为 **11-20 收盘**，京报网稿件把 T-1 数据写成了 T 日。本报告统一采用乙组（与正文 2.1 表格 `125.5 美元 / −14%` 一致）。这提示除已连续四期出现的「同月同日跨年旧稿」外，还存在**「T-1 数据被标注为 T 日」的错位稿**变体；凡遇两组看似冲突的行情数字，先用「相邻交易日涨跌幅 + 市值差」交叉验证，往往能判定是时点差异而非错误。
