**个股层面几乎是"硬件链的定向清算"**：英伟达 -4.12%、台积电 -6.34%、美光 **-7.62%**、英特尔 **-7.02%**、闪迪 **-8.58%**、AMD -5.58%、应用材料 -5.47%、ASML 近 -6%、博通 -3.92%。光通信更惨：Lumentum -8.48%、Ciena 跌超 8%、Marvell -7.27%、康宁近 -7%。七巨头全线下跌（谷歌 -3.85%、亚马逊 -3.34%、特斯拉 -2.69%、Meta -2.38%、微软 -1.12%、苹果 -0.98%）。

**唯一逆势的是"必选消费"**：麦当劳 +1%，沃尔玛、开市客小幅跟涨。

**直接触发点**：11-16，半导体研究机构 **SemiAnalysis 在模型更新中大幅下修 AI 算力预测**：

| 指标 | 修正幅度 | 具体数字 |
|---|---|---|
| 2028 年全球 AI 加速器资本开支 | **-28%** | — |
| 2029 年 | **-41%** | — |
| 2030 年 | **-40%** | 1.531 万亿美元 → **9,230 亿美元**（-6,080 亿） |
| 2026–2030 加速器逻辑硅片出货面积 | 累计 **-17%** | 2027/-13%、2028/-16%、2029/-24%、2030/-15% |
| HBM 出货量 | 2028 **-30%** | 9.0EB → 6.4EB（2029 10.3→7.9EB、2030 10.9→9.6EB） |

三个细节决定了这份下修的杀伤力：

1. **削减不是平均分配的**。SemiAnalysis 明确 **英伟达占了硅片出货面积削减幅度的 66%**——它不是说"AI 硬件整体降温"，而是说"降温主要发生在英伟达的产品线上"。
2. **驱动力是收入端，不是供给端**。报告把主因归于"前沿 AI 实验室第三季度新增 ARR 增速放缓"，导致对全生态可产生 Token 收入的重新审视；其次是"债务与股权投资者对缺乏超大规模云厂商采购承诺的项目投资意愿减弱"，直接冲击数据中心的土地、电力与建筑主体（Shell）开发。
3. **政治变量是"额外项"而非主因**。美国中期选举结果导致原计划 2027H2–2028H1 投产的数据中心中 **5.8GW 被推迟**，监管因素进一步压缩 2028 年容量。报告特意强调这只是附加因素。

**为什么值得关注（分析）：** 过去两周市场的争论是"AI 资本开支是否见顶"，各方都是定性判断。SemiAnalysis 的独特之处在于它给的是一个**可被证伪的自下而上模型**：如果 2027 年 Q1 台积电 CoWoS 产能利用率、HBM 合约价、以及美国数据中心并网排队长度都没有按它下修后的曲线走，这份报告就会被推翻；如果按它走，那么今天 7,400 点的标普对应的是"2028 年 9,230 亿美元资本开支"，而不是"1.5 万亿"。**这是本轮行情第一次有人把 AI 的终局从"叙事"换算成"装机量"，而这恰恰是最容易被季度数据检验的东西。**

**为什么值得关注（分析）：** 同一份下修，在三个市场被定价出三种幅度：美股 -5%、韩股 -3.6%、台股 -6%。台股跌得最狠不是因为它更依赖 AI，而是因为**它的成分股就是 SemiAnalysis 模型里的物理对象**——硅片面积、CoWoS 产能、机架组装。这给出一个可用的观察框架：**当"AI 预期"下修时，越靠近实体产能的市场跌得越深；当"AI 预期"上修时，也应是它们先涨。** 11-16 台股的 -6% 是一次"物理层"的重新定价，比纳指的 -2.49% 更接近真相。

值得单独记一笔：**台积电拟按客户信用额度供应产能**（11-16，台湾工商时报引业内人士）。随着"AI 循环融资"疑虑加深，台积电把客户财务与数据中心建置纳入需求评估，按其资产负债表拟定信用额度，考量历史损失率、竞争力与营运展望，**下单金额超出额度就须额外拿现金支付**；部分客户还需先付款才能保留指定产能。

这是本轮 AI 周期里最不寻常的一条供应链新闻。代工厂给客户做信用评估，意味着**上游已不再相信下游的"承诺订单"**。结合英伟达截至 7 月已排定的 **2,790 亿美元供应与产能承诺（其中 2,670 亿美元将在未来两年半内到期）**，台积电的动作可以读成一句话：它要在这个窗口期内，把"承诺"换成"现金"。

### 2.1 AI 与 Agent

#### 2.1.1 英伟达双线出手：Vera CPU 机架级平台 + 量子-经典协同设计（11-16）

英伟达 11-16 宣布两项发布：

**（一）Vera CPU 机架级平台**，面向高性能计算（HPC）。官方口径：**Vera 为"智能体科学（agentic science）"带来更高性能，能效比 x86 CPU 提升一倍**；完整平台将由**戴尔科技、HPE、联想、Supermicro** 提供。

**（二）与 IBM、费米国家加速器实验室（Fermilab）合作的量子-经典协同设计平台**，在纠错方面取得突破：新的 **TCBP-JOBS 解码器**在 CUDA-Q QEC 中为量子纠错研究带来最高 **13,000 倍**加速。

**为什么值得关注（分析）：** 这两件事放在一起看，英伟达在做的是**"把护城河从 GPU 移到系统"**。Vera 是英伟达首款自研数据中心 CPU，意义不在性能数字，而在于：当推理与智能体负载的计算特征从"大规模矩阵乘"变成"大量短小的调度 + 工具调用 + 状态维护"时，**GPU 的利用率会被 CPU 侧的调度能力掐住脖子**。把 CPU 也做进机架并宣称 2x 能效，是在告诉客户："你不需要买别家的 CPU 来配我的 GPU。"

而量子纠错解码器的 13,000x 加速，是更长线的期权：**量子计算商业化的瓶颈从来不是量子比特数，而是纠错解码的实时性**。英伟达选择在 CUDA-Q 上做这件事，等于提前把"量子计算的经典协处理器"这个位置占了。

#### 2.1.2 谷歌云公布 Ironwood（TPU v7）10 项基准：卖点从"训练"转向"智能体周转率"（11-16）

谷歌云公布基于**第七代 Ironwood TPU** 的 10 项测试结果，涵盖前沿预训练以及**首个面向智能体强化学习（agentic RL）的 MLPerf 基准**。

关键数据：在智能体强化学习场景下，**640 块 Ironwood TPU 在 18.02 分钟内达到目标模型的编码基准目标准确率**，同时运行代码生成与学习，**使训练芯片的等待时间占比低于 3%**。

**为什么值得关注（分析）：** "等待时间占比低于 3%" 这个指标比任何 FLOPS 数字都更能说明问题。智能体强化学习的负载特征是**生成-执行-反馈的串行循环**：模型生成代码 → 沙箱执行 → 拿到结果 → 再训练。这个循环里，芯片大量时间在**等 CPU、等沙箱、等 I/O**，而不是在算。谷歌把"等待时间 <3%"作为卖点，等于宣布：**TPU 的竞争对手不是 GPU 的算力，而是 GPU 集群的空转率。**

这与 SemiAnalysis 的下修形成有趣的对照：一边是研究机构说"2028 年不需要那么多加速器"，一边是云厂商在证明"同样的加速器能干更多有效工作"。**如果后者成立，前者的下修就是对的——不是因为需求少，而是因为效率高。**

#### 2.1.3 MCP 安全三连爆：Agent 生态的第一个系统性风险在工具层

过去一周内，三份独立研究指向同一个结论：**MCP（Model Context Protocol）正在重演 npm 的供应链剧本。**

**（一）Corelight《藏在 MCP 服务器里的供应链风险》（11 月）**

核心发现：**一台配置到"某一版本 + 某一 commit"的 MCP 服务器，在五周内实际运行了 15 套不同的依赖集合**。原因是一步式启动器 `uvx` 忽略了已发布的 lock 文件，每次重建都从 PyPI 重新解析约 60 个传递依赖——**69 个包中有 23 个版本发生了变化，包括 cryptography 库与 MCP SDK 本身**。

更广的样本：**35 个受审查的 MCP 服务器中，有 23 个的推荐安装方式会从公共 registry 拉取最新依赖**；某助手配置的服务器在一周内向 11 个管理系统发起了 **1,600+ 次连接**。

风险机制：MCP 服务器以**安装用户的权限**执行，且通常持有它所连接的安全工具（防火墙、SIEM、云控制台）的**管理员凭据**。攻击者只要污染任一传递依赖，就获得了"带管理员凭据的代码执行上下文"。

**（二）Palo Alto Networks Unit 42：级联信任（cascading trust）**

一个被攻陷的 MCP 服务器可以操纵 agent **误用其他可信工具**：一旦 agent 把受损服务器的输出接受为有效上下文，该服务器就能注入指令，让指令"跟随" agent 进入后续对其他可信服务器的调用。受控测试中，**给单个 agent 连接 5 个 MCP 服务器，攻击成功率达 78.3%**。

风险主要来自协议的 **sampling 特性**（服务器可主动请求 LLM 补全），带来三类攻击：**资源盗用**（耗尽算力配额）、**会话劫持**（注入持久指令）、**隐蔽工具调用**（在用户不知情下触发文件系统操作）。协议的授权模型已在演进：引入 OAuth 2.1 + Resource Indicators，2026 年 7 月起以 OAuth Client ID Metadata Documents（CIMD）**弃用动态客户端注册（DCR）**。

**（三）Kubeshark MCP 两个 CVE**

- **CVE-2026-129236**：参数注入可劫持集群镜像（需 `--allow-destructive` 与足够 kubeconfig 权限）→ 单次注入即可达成 **cluster-admin 接管**。引入于 commit `0bbbb473`（2026-02-06），首发 v53.1.0。
- **CVE-2026-129235**：`download_file` 的 `dest` 参数未受限 + `path` 未做 allowlist → **任意文件写入**，且 Hub 默认无认证，可端到端读出含凭据的抓包 PCAP。引入于 commit `eb7dc42b`（2026-03-04），首发 v53.1.0。
- 修复版本：**v53.4.0**（为参数注入加 `--` 结束符；新增 `secureDownloadDest` 限定基目录、拒绝 `..` 与绝对路径、解析符号链接后复检、`O_NOFOLLOW` 打开）。

另有一份 **Glow Labs 的 "MCPhantom" 研究**（11 月）：AI 编码 agent（Claude Code、Cursor、Codex CLI 等）会**从训练数据里"回忆"出已被归档的 Anthropic MCP 参考服务器并安装它们**——不是因为用户要求，而是因为这些包名大量存在于训练语料中。这些已归档包带有 **4 个高危漏洞（含可通过 prompt injection 触发的 Puppeteer 服务器 RCE）**，自 2025 年 7 月以来 npm 下载量已超 **1,700 万次**。报告的关键判断是：**这里面没有攻击者**——agent 自己的过时知识选中了有漏洞的包，因此 EDR、SCA 与 harness 护栏都不会报警。

**为什么值得关注（分析）：** 这四条汇总起来，构成了一个对 2026 年下半年 AI 工程最重要的判断：**Agent 的安全边界不在模型，而在"工具描述"和"依赖图"这两块没人当代码审的文本。**

- 工具描述（tool description）会被加载进**模型的上下文窗口，作为可信指令文本**——它和 system prompt 是同一优先级。这意味着攻击面从"代码注入"扩展到"自然语言元数据注入"。
- 依赖漂移意味着**三月份审过的服务器，十一月份是另一份软件**，但配置里还是同一个名字。
- MCPhantom 则揭示了一个新类别：**不是供应链投毒，是"训练数据造成的系统性误选"**。这类问题无法通过"别用不可信的服务器"来防御，因为模型认为它是可信的——它来自官方仓库的历史版本。

可落地的缓解措施（综合三份研究）：pin 到 commit 而非 tag、用 hash-pinned lock 装进每服务器独立环境、直接启动已安装的服务器而不经过会重新解析的启动器、关闭启动时更新检查、按最小权限授予每个服务器的凭据、把工具描述纳入 code review、对每次工具调用记录完整参数（多数 tool poisoning 只能在审计日志里事后发现）。

#### 2.3.2 kiri：2.5 毫秒启动容器的 Rust 运行时

`libracoder/kiri` 是本周期 star 增速最快的项目之一（周窗口 +3,147）。它是一个**用 Rust 写的轻量容器运行时**，定位是 Docker Desktop 与 OrbStack 的替代品：

- **说 Docker Engine API**，所以 `docker` CLI、Compose、buildx 都继续可用；
- **10 MB 定制内核 + 极小的 guest agent，容器启动约 2.5 ms**；
- 一条命令拉起**单节点 Kubernetes 集群**；
- 每个容器分配**本地 HTTPS 域名**。

**为什么值得关注（分析）：** 2.5ms 这个数字的意义不在跑分，而在**它把"容器"从"部署单元"变成了"函数调用"**。当容器启动比一次 HTTP 往返还快时，按请求起容器（而非常驻）在经济上变得可行——这对 **AI agent 的代码执行沙箱**是一个直接可用的原语：每个工具调用起一个 2.5ms 的隔离环境，跑完即销毁，比"常驻沙箱 + 清理"安全得多。

Rust 重写 Docker Desktop 这条赛道（OrbStack 已证明可行）现在有三家在做，说明"本地开发环境的容器层"是一个被低估的高价值环节。
