### 1.1 AI 与 Agent

#### 1.1.1 Anthropic 把 Messages API 从 Python 迁到 Rust，「验证先于生成」成为过去 24h 最硬的一手

**事件（发生日期：11-25 官方工程博文，11-26 成为 X 上讨论度最高的 AI 话题）**：Anthropic 发布工程复盘，把服务客户及 Claude Code / Cowork 的 Messages API 核心请求链路从 Python 迁到 Rust。该 API 2023 年用 Python 写成，2024 年初至 2026 年秋流量增长约 **1800 倍**，单条请求需完成校验、转提示词、分词、安全分类，再把返回的 token 拆解为文本/思考/工具调用，Python 在对象创建与内存释放上的开销已成瓶颈。Claude 约**一周**写出核心请求路径第一版；截至 2026 年 5 月公司合并上线代码中**超 80% 由 Claude 编写**。

难点不在生成而在验证：迁移中 Python 版仍在迭代（正确性标准本身在变）、模型回复非确定性（输出不同≠有 bug）、且**不能读取客户请求**。做法是把生产 Messages API 本身当作 verifier，用真实影子流量比对新旧实现——**模型只运行一次、把输出回放给 Rust 版**，逐阶段比对；只记录「处理步骤 / 首个差异字节 / 两侧长度」等指纹，不读原文；再自动派 Claude agent 团队按指纹分组定位、提交修复，由工程师在 PR 关卡判断「差异是 bug 还是有意的改动」，并搭三层循环（内层沙箱快速复现 / 外层生产影子验证 / 记忆循环沉淀踩坑）。

关键数字：4 月 Rust 版通过约 **98% 集成测试，但真实生产输入仅约 1/4 完全匹配**，8 月升至 **99.6%**；审计移植后的测试发现**超 100 处断言被弱化**；仅 20 个二元开关就有超百万种配置组合（单模型跑完一次需 12 天）。早期「只把输出解析改成 Rust」的增量方案仅降 CPU 8%～10%，且每 token 要跨 Python/Rust 边界三次，被放弃。最终**每请求 CPU 降约 70%、首 token 中位时延降约 20%，全程未停服、未冻结功能开发**，对公流量已于 2026 年 9 月切换。

**为什么值得关注**：这是「AI 写代码」向「AI 改造生产系统」过渡的一份可复制方法论。它把行业注意力从提示词/模型能力，拉回到**「先建立可信的校验信号，再让 Agent 在快—慢—记忆三层循环里自行试错，人只负责定义什么算正确」**。对自建编码 Agent 的团队，投入重点应从提示词工程转向校验器、影子回放与差异指纹。同时「98% 测试通过但生产匹配率 1/4」是对所有「测试全绿即可上线」直觉的直接反证。**注意**：70%/20%/99.6% 等均为 Anthropic 自述，尚无第三方独立复现。

#### 1.1.2 OpenAI Private Inference 进入小范围客户测试

**事件（11-26）**：Sam Altman 宣布 OpenAI Private Intelligence 下的 **Private Inference** 已与一小群客户开始测试。官网标为 **Alpha / API Preview**，用**机密计算（confidential computing）+ 可验证控制**保护推理过程中的提示词与回复；同一条还提到零数据保留（ZDR）+ Private Safety Processing，可在不把底层内容交给 OpenAI 员工的前提下做自动化安全审查。DevDay 2026 已预告秋季预览，本次是「开始测试」而非新品类首次披露。

**为什么值得关注**：对金融、医疗等强监管行业，「数据不出边界」的推理正在成为厂商竞争点。**需要辨析**：网上有传言写成「在用户自己的托管上做推理」，与官网及 Altman 原文不符——官方口径是机密计算与可验证控制，不是「模型跑在你自己的机器上」。Alpha 阶段应先当能力边界声明，等独立评估与合同条款出来，再判断能否进入真正敏感的工作流。

#### 1.2.2 Vite 8「换芯」Rolldown：实测构建提速 3.19 倍（近期背景，日期未独立确认）

**事件**：技术解析稿称 Rolldown（VoidZero 主导、Rust 重写的 Rollup 兼容打包器）已在 **Vite 8 正式合入主线**，esbuild + Rollup 的「双引擎」退役；复用 Oxc 生态（parser / transformer / resolver / minifier）内嵌，省去 esbuild 作为独立服务进程的通信开销，并对无依赖模块多线程并行。实测**构建提速 3.19 倍**，项目越大、依赖越多提升越明显。`build.rollupOptions` 仍然有效，纯转换类插件基本可平移。核心价值被表述为解决「**开发—构建一致性**」：过去 `define: { __DEV__: true }` 在 dev 正常，但 build 时 esbuild 会整块移除条件分支，而 Rollup 插件可能已在 transform 钩子里改过 AST，直接导致线上 bug；Rolldown 用一套代码基座同时支撑 dev 模块解析与生产打包。

**为什么值得关注**：两类插件要重点验证——依赖 Rollup 内部对象/非公开 API 的，以及深度依赖 `renderChunk` / `augmentChunkHash` 等输出阶段钩子的。若你在做构建产物分析、自定义 sourcemap 或多环境差异化 bundle，这次「换芯」接近必选项而非可选项。**注意**：以上为技术解析/实测稿，非官方发布公告，日期未独立确认，标为近期背景。
